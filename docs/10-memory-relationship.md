# 記憶と関係性

## 3層の情報

基本人格は本人が編集・承認した`agent_profiles`の版。交流が自動変更しない。短期記憶は現在の会話の発言列で、DBの`messages`を読み直せる。長期記憶は本人視点の`memories`で、交流後に生成する候補。MVPでは会話要約を保存し、本人が閲覧・削除可能な記憶候補を少数抽出する。抽出は「会話で述べられたこと」と「本人の確定事実」を混同せず、出典conversation IDを必ず持たせる。

## 記憶の流れ

1. 完了会話の要約を各参加者視点で作成し、PII/秘密混入を検査する。
2. 1セッション最大3候補にし、重要度1〜5を付ける。出典と作成時刻を残す。
3. 正規化テキストのハッシュを`dedupe_key`とし、同一候補は更新せず出典を追加する正式版拡張を予定。MVPは重複を棄却する。
4. 次回交流では同じ相手に関係する上位最大5件と直近会話要約のみ取得し、トークン上限内に切る。
5. 本人が削除した記憶は即時に検索対象から外し、DBから削除。削除した内容を他の要約へ再挿入しないよう、出典会話との参照を管理する。

検索は`agent_id,status,importance`索引と日付で絞る。件数がAIごとに数百件を超え、評価セットでキーワード検索の再現率が不足した時にpgvectorを検討する。pgvectorを入れる場合も埋め込み対象から非公開情報を除き、再生成・削除の経路を定義する。

## 関係性

`agent_relationships`は2体のIDを昇順に正規化した無向の交流集計。完了会話1件につき回数を1増やし、共通の公開興味を保存。表示ラベルは0=初対面、1〜2=顔見知り、3以上=よく交流する相手。共通興味は補助表示であり、本人同士の友人関係や相性を断定しない。会話削除時は残存完了会話から再集計し、関係性が消える場合は行を削除する。MVPはリスト表示、グラフ可視化は正式版。[DB](05-database-design.md)、[画面](12-frontend-screens.md)参照。


## #25の先行する閲覧・削除API（PR #49）

#25で先行実装した閲覧・削除境界を、#22/PR #62の生成・Worker連携と統合する。
本人の候補を削除すると、同じ出典の本人の他候補も物理削除し、出典/重複キーの抑止記録を残す。
元の会話・相手の候補は変更しない。出典NULLなら選択した候補とキーだけを削除・抑止する。
候補の本文・所属・出典・重複キー・作成日は不変とし、後から削除済み本文に書き換えない。
DB挿入ガードは抽出実装が抑止記録を確認し忘れた場合も再投入を拒否する。

一覧は記憶180日と出典会話の可視性/90日保持を両方満たす範囲だけ。削除要求を行った参加者の
派生候補は双方から直ちに非表示にし、出典の物理削除ではFK CASCADEで消す。
関係一覧は可視completed会話から現在の回数を計算し、消えた会話の古い集計を見せない。
共通興味は承認済みの公開人格から取得し、本人からのブロックだけを操作状態として返す。


## #22の生成・次回入力・パージ連動

記憶候補は追加のLLM呼出を行わず、完了会話の独立安全判定済み発言を引用して抽出する。
会話要約は#95の別処理で生成する。
ローカル安全検査とWorkerの禁止秘密値の照合を通った発言だけから、本人ごと最大3候補を作る。
「自分のAI／相手のAIの会話中の発言・確定事実ではない」と明示し、出典会話・重要度3・正規化hashを保存する。
会話要約は意味をまとめた共通の生成要約として保存し、次回入力時に本人視点の呼称へ変換する。

独立Workerは`conversation_events(kind='completed')`を`memory_completions`で消費する。
候補・正規化した関係ペアの回数／最終交流日／承認済み公開興味・完了印は同じtransactionで確定する。
要約はその後、独立した生成/判定と保存を行う。
失敗は全体rollbackし、再起動時に未処理eventから再開する。並行Worker・再試行でも候補や回数を増やさない。
通知・Discordのconsumer進捗は変更しない。削除要求済み／AI削除済み／90日期限切れの出典は完了印だけ残し抽出しない。

各ターンの`LLMExecution.conversation_turn`が同じ相手の上位最大5記憶と直近要約をDBから取得し、
`quoted_memories`／`quoted_summary`という引用データで渡す。任意の記憶配列を呼出元から注入しない。
記憶180日・出典90日・参加者の削除状態・本人の出典／hash抑止を再検査する。
削除hashと同じ発言が別の出典にもある場合は、その要約も入力しない。
送信前（count_tokens後を含む）・独立安全判定前・保存前に取得時の記憶／要約と照合し、
削除や出典の非表示を検知した呼出は中止する。既に始まった外部呼出の費用は記録し、結果は保存しない。
トークン超過時は要約、優先度の低い記憶、古い発言の順に削り、承認人格や安全指示を削らない。

本人の削除は#25の`memory_read.forget`と挿入ガードを共用する。
「同じ会話から作られた記憶もまとめて削除されます」と事前に説明し、元の会話と相手の記憶は保持する。
`blocked`は本人AI→相手AIだけを返し、マッチングは双方のブロックを除外する。

会話の物理DELETEでは既存FKが記憶／抑止／完了印をCASCADE削除する。
`20261114140000_memory_relationship_purge.sql`のBEFORE DELETE triggerが、参加者が消える前に
残存可視completed会話から関係キャッシュの回数・最終交流日を再計算し、0件ならペア行を削除する。
内部`memory.delete_conversation`と直接SQLのどちらも対象。アカウント全体の非同期パージ運用は#30の担当範囲。

検証は`tests/db/test_memory_db.py`（実DB＋合成Auth/LLM、独立Worker入口を含む）と既存#25のAPIテスト、
`supabase/tests/memory_suppression.test.sql`（RLS・全権限拒否・CASCADE）で行う。


## 意味をまとめる会話要約（#95）

発言の単純連結は要約として保存しない。独立Workerの`summary.summarize_one`が、
記憶抽出済みのcompleted会話から、未処理または旧列挙形式の要約を1件処理する。
全発言の話者・順序を引用JSONとして渡し、話題、共通点/相違、到達点を2〜3文/最大180文字にまとめる。
本人の事実や未成立の合意を創作しない。同じ挨拶/質問しかない会話は、進展がなかったことをまとめる。

生成と独立判定を費用付きLLMExecutionで行い、purpose=summaryの会話一意制約で重複を防ぐ。
日次・会話・全体の残予算に収まる参加者1体へ最大$0.012960を予約する。
通常の会話予約や費用上限は変更せず、残枠不足なら未作成とする。
既知費用は必ず記録し、専用のllm実行キーで未使用予約を解放する。結果不明は予約を維持する。

送信のたびに双方の有効招待・交流ON・承認版・ブロック・削除/90日保持を確認する。
出典抑止と削除hashがある場合も入力/公開しない。入力発言が変化した場合は生成物を破棄する。
成功した生成物だけをsummaryへ保存し、記憶候補や会話本文は書き換えない。
失敗やbudget不足で発言列挙へフォールバックしない。会話完了と要約完成は非同期である。
通常終了済みでも判定/保存前に権限が変われば公開しない。失敗/課金不明の自動再試行はしない。
