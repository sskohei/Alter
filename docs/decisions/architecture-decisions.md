## #14 Sonnet正式採用（2026-11-13、最新決定）

決定者sskoheiが「正式にsonnet採用でいきましょう。それを前提として実装し、push」と指示。
ADR-008と上の未決定事項を更新する。以前のHaiku採用保留は当時の評価記録である。
採用モデルは`claude-sonnet-5-5`、Claude直接API、API version `2026-10-21`、
adaptive thinking / effort low、出力最大512 tokens（thinking込み）、入力上限8192 tokens。
構造化Utterance、キャッシュ/外部ツールなし、未知の課金・拒否・打切りの自動再試行なし。
単価は2026-11-13の公式通常価格、入力$2 / 出力$10（各100万tokens）。
実装の正本は`alter_domain.llm_selection`。モデル変更は単価と評価の再確認を伴う。

根拠は[Sonnet限定評価](../../evaluations/llm/sonnet-review-2026-11-13.md)：
単発5ケース＋4会話、31生成でschema成功31/31、今回の4場面では未記載の体験の断定なし。
採用はこの証拠と利用者判断に基づく。全10場面/反復評価/人による4/5以上の採点を
実施済みと扱わない。残りの品質受け入れは#37で追跡する。

Haikuは未記載の体験・未経験の断定が残り不採用。Opus/他社/自動fallbackはMVP対象外。
会話$0.05/体・日次$0.20/体の上限を維持し、Sonnetの見積額が残枠を超える呼出は止める。
最大token数で8発言を必ず生成する保証はしない。[費用再計算](../20-cost-estimation.md)を参照。
#18はこの採用設定を使って本番adapter・全呼出の予約とusage・アプリmoderationを接続する。
#16の本人同意APIを含む公開条件を満たすまで本番の自律交流を有効化しない。

## #14 PR #57レビュー: 既定予算に合わせる入力上限（2026-11-14）

[レビュー指摘](https://github.com/sskohei/Alter/pull/57#issuecomment-6854464943)に対し、
入力上限を8192から3072 tokensへ縮小する。4096でも1体4発言が$0.053248となり、

DB既定値の引上げも、会話単位から発言単位への予約方式の変更も行わない。
入力上限はsystem/schema/人格/引用context/履歴/計数余裕をすべて含む。

共通の`session_generation_reservation()`は生成4回分の最大予約を返す。
MVPの引用記憶/要約は追加LLMなし。追加moderationの有料呼出は残枠$0.004944以内で
別途見積もるか生成量を減らし、#18の本番接続前に全呼出を予約へ含める。
再試行は未課金確認済みのみ。結果不明時は停止・予約保持とし、予算に含まれない再生成をしない。
過去の評価証跡は当時の8192上限のまま保ち、3072で実評価済みとは記載しない。

Render Workerのキー名は`ANTHROPIC_API_KEY`へ統一する。main/#69の同意設定を取り込み、
同意文面確定前の`ALTER_CONSENT_VERSION`空欄とON拒否を維持する。docs/14に設定先を記載する。

## #20 Workerと費用付き実行の接続（2026-11-14、PR #61）

#19の`conversation.run`と#18の`conversation_turn`を独立Workerで接続する。
生成と判定の実費は各応答後に短いtransactionで記録し、発言本文を待って既知費用を失わない。
古いleaseは発言/状態を書けないが、既知費用の記録は継続する。呼出前markerにより、
費用確定後・本文保存前にクラッシュしても同じターンを再生成しない。
判定だけが一時失敗したケースも再生成しないため、Workerの再試行は全処理が未課金の場合に限る。
完了eventとWeb通知は最終発言/終了状態/残予約解放と同じtransaction。
API/Botが未実行の会話を取り消した場合もWorkerが予約を精算する。
課金exactly-onceは保証せず、未完/結果不明は#36で照合する。実品質は#37、本番配備は#34。
