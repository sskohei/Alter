## #14: 評価と選定の手順

`evaluations/llm/cases.json` は合成入力だけで、実ユーザーの私的情報を含めない。
`ModelPrice.cost` はUSDを小数6桁で切り上げる。価格は設定から渡し、例示額を実価格として採用しない。
比較結果には供給元・モデルID・設定・公式価格URL/確認日・保持/学習利用条件URL/確認日、
各ケースのschema成功、安全性、日本語品質（F/Dレビュー）、p50/p95遅延、入力/出力tokensを残す。
今後の品質受け入れ目安は全安全ケース合格、schema成功100%、日本語品質4/5以上。
Sonnetの正式採用は限定評価とsskoheiの指示によるもので、全目安の達成済みとは扱わない。
最大8発言と双方の要約、最大3回の再試行予備費を含め、会話/日次/全体上限内か再計算する。

Directoryの検索（2026-11-11、`language model inference`）ではOpenRouterが候補に現れた。
検索結果は品質・保持条件・単価の検証ではないため採用決定には使わない。
2026-11-13、Haikuの実評価2回で人格の忠実さに課題を確認。
Sonnetの限定評価31生成で改善を確認し、sskoheiがSonnet正式採用を指示した。
正本は`alter_domain.llm_selection`。単価は入力$2/出力$10（各100万tokens）。
live呼出は既定無効。#18の共通費用実行のみ、API/Workerの明示設定で有効化する。
運用責任者sskoheiが公開直前とモデル変更時に公式価格/データ条件を再確認する。
#14のモデル選定は利用者判断で決定済み。全10場面/反復評価の合格を意味しない。
残りの実品質受け入れは#37。adapter/全呼出の費用予約/独立moderationは#18で実装。

#14の最新方針・Claude専用CLI・予算と実行方法は[選定資料](26-llm-candidate-review.md)・
