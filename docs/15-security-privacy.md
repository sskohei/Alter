# セキュリティとプライバシー

## 境界と保護策

| 対象 | 実施策 | 確認方法 |
|---|---|---|
| 認証/認可 | Supabase Auth、FastAPIのJWT署名/claim検証、所有権SQL条件、全表RLS | 別ユーザーIDで403/404、RLS直接アクセス拒否 |
| API濫用 | ユーザー/IP単位のレート制限、フォーム長制限、Idempotency-Key | 429と再試行、重複要求テスト |
| LLM | 承認済み人格だけ、非公開情報を除去、相手発言はデータ扱い、出力schema/モデレーション | 悪意ある相手発言のMockテスト |
| 秘密 | OAuth/Bot/LLM/DBキーをRender Secret。ログ・エラー応答に載せない | secret scanning、ログ検査 |
| 費用 | 日次/会話予算の予約、運営全体上限、上限時停止 | 競合ジョブで上限超過しないテスト |
| Discord公開 | 双方のギルド別同意、管理者設定、投稿直前再確認、メンション無効 | 不同意/解除後の未配信テスト |
| 監査 | 設定変更、連携、削除、公開のactor・時刻・結果。本文は記録しない | `audit_events`レビュー |

非公開人格情報は通常API応答、公開プロフィール、Discord投稿、通知、LLMプロンプトから除外する。APIがAES-GCMで暗号化してDBへ保存し、鍵版とnonceを暗号文に含める。復号は所有権を確認した編集用APIだけに限定し、鍵`PROFILE_ENCRYPTION_KEY_V1`はAPIのRender Secretに置く。鍵ローテーション時は新しい版で書き込み、旧版を読める期間に再暗号化する。機微情報を入力しない案内も出し、収集を最小にする。Storageのアイコンは種類別のbucketとMIME/サイズ検証を使い、実行可能ファイルを拒否する。

## 保存・削除・同意

| データ | 初期保持 | 削除時 |
|---|---|---|
| 会話/発言/Discord配送ID | 90日 | 関連会話を参加者双方から削除し、Discord投稿削除を試行 |
| 記憶 | 180日で再評価 | 本人の要求で即時に検索対象外・削除 |
| 通知 | 90日 | 会話関連は会話削除に連動 |
| 使用量 | 12か月 | 会計・不正調査に必要な非本文データとして期間後削除 |
| 監査 | 180日 | 秘密本文なし。アカウント削除時は個人識別子を匿名化 |
| Discord連携 | 解除まで | OAuth tokenを破棄、未配信を中止、メタデータ30日後削除 |

自律交流は初期OFF。ON操作では「他者AIとの交流」「会話保存」「Webの参加者閲覧」を分けて説明する。Discord公開は別のギルド別同意で初期OFF。公開済み投稿を確実に削除できないこと、AIは本人と同一ではないことを同意直前と会話表示に明示する。第三者へ本人情報を直接送る行為はMVP対象外。アカウント削除は [認証](06-authentication-authorization.md) の順序で実施し、処理完了を通知または確認ページで示す。個人情報の最終保存期間・利用規約は法務確認の未決定事項。

DiscordのAPI制限は [Bot仕様](11-discord-bot.md) の通り。Rate limitを固定値にしない。Discord過去メッセージを人格作成のために収集しない。

MVPのAPI目安は認証済みユーザー60リクエスト/分、書込10リクエスト/分、人格提案3回/日。初期はAPI 1インスタンスのメモリ内制御にし、LLM費用はDB台帳で厳格に止める。APIを複数台に増やす前に共有ストア型のレート制限を導入する。制限値は負荷試験後に調整し、429に`Retry-After`を返す。
