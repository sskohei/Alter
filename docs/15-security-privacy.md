# セキュリティとプライバシー

## 境界と保護策

| 対象 | 実施策 | 確認方法 |
|---|---|---|
| 認証/認可 | Supabase Auth、FastAPIのJWT署名/claim検証、所有権SQL条件、全表RLS | 別ユーザーIDで403/404、RLS直接アクセス拒否 |
| API濫用 | ユーザー/IP単位のレート制限、フォーム長制限、Idempotency-Key | 429と再試行、重複要求テスト |
| LLM | 承認済み人格だけ、非公開情報を除去、相手発言はデータ扱い、出力schema/モデレーション | 悪意ある相手発言のMockテスト |
| 秘密 | OAuth/Bot/LLM/DBキーをRender Secret。ログ・エラー応答に載せない | secret scanning、ログ検査 |
| 費用 | 日次/会話予算の予約、運営全体上限、上限時停止 | 競合ジョブで上限超過しないテスト |
| Discord公開 | 双方のギルド別同意、管理者設定、投稿直前再確認、メンション無効 | 不同意/解除後の未配信テスト |
| 監査 | 設定変更、連携、削除、公開のactor・時刻・結果。本文は記録しない | `audit_events`レビュー |

非公開人格情報は通常API応答、公開プロフィール、Discord投稿、通知、LLMプロンプトから除外する。APIがAES-GCMで暗号化してDBへ保存し、鍵版とnonceを暗号文に含める。復号は所有権を確認した編集用APIだけに限定し、鍵`PROFILE_ENCRYPTION_KEY_V1`はAPIのRender Secretに置く。鍵ローテーション時は新しい版で書き込み、旧版を読める期間に再暗号化する。作成リクエストの再送照合には暗号化鍵と独立した版付きHMAC鍵を使用し、入力本文は保持しない。
HMAC鍵の交換では新旧鍵を配布してから現行版を切り替え、旧版の最終作成成功から24時間は旧鍵で照合できるようにする。
環境変数・再送保証・期限後の扱いは[API設計](07-api-design.md)を参照する。
機微情報を入力しない案内も出し、収集を最小にする。Storageのアイコンは種類別のbucketとMIME/サイズ検証を使い、実行可能ファイルを拒否する。

収集は本人が入力した一般的な人格/興味と運用に必要な識別子等に限定する。非公開欄は任意・空が既定で、機微情報・第三者の秘密を入力しないよう案内する。招待管理・削除対応・鍵管理の責任者はsskohei。暗号鍵は90日ごと、および漏えい疑い/権限変更時に交換し、新版書込・再暗号化・復元検証後に旧鍵を廃止する。具体的手順と文案は[運用契約](23-invitation-consent-operations.md)を参照。

招待データはDBで管理し、APIと運営専用CLI以外の直接アクセスを禁止する。運営操作の監査にprovider ID・Supabase sub・トークンを複製しない。10人枠と失効/AI停止/未配信取消の原子性は[招待契約](23-invitation-consent-operations.md)に従う。

## 保存・削除・同意

| データ | 初期保持 | 削除時 |
|---|---|---|
| 会話/発言/Discord配送ID | 90日 | 関連会話を参加者双方から削除し、Discord投稿削除を試行 |
| 記憶 | 180日で再評価 | 本人の要求で即時に検索対象外・削除 |
| 通知 | 90日 | 会話関連は会話削除に連動 |
| 使用量 | 12か月 | 本文なし、アカウント削除時は再識別可能な紐付けを除去し期間後削除 |
| 監査 | 180日 | 秘密本文なし。アカウント削除時はactor/resource/metadataの個人識別子を匿名化 |
| 招待・許可identity | 有効期間中 | 失効後30日以内、アカウント削除要求後30日以内の早い期限で識別情報をパージ。存在しない招待も拒否 |
| Discord連携 | 解除まで | OAuth tokenを破棄、未配信を中止、メタデータ30日後削除 |

保持値は法務確認前の暫定運用値。期限起算・記憶再評価・30日以内パージ・Discord配送IDの退避・バックアップ/外部LLM残存の扱いは[運用契約](23-invitation-consent-operations.md)に従う。削除要求時点で共有会話と派生データを双方から参照不可にする。

人格承認、自律交流、Discord全体公開/ギルド別公開、Discord DMは独立した本人操作で初期OFF/未承認。同意文面版・本人・対象・時刻・結果を本文なしで監査する。自律交流は初期OFF。ON操作では「他者AIとの交流」「会話保存」「Webの参加者閲覧」を分けて説明する。Discord公開は別のギルド別同意で初期OFF。公開済み投稿を確実に削除できないこと、AIは本人と同一ではないことを同意直前と会話表示に明示する。第三者へ本人情報を直接送る行為はMVP対象外。アカウント削除は [認証](06-authentication-authorization.md) の順序で実施し、処理完了を通知または確認ページで示す。個人情報の最終保存期間・利用規約は法務確認未完了。[運用契約](23-invitation-consent-operations.md)の公開ゲートに従い、sskoheiが2026-11-17または本番公開前日の早い方までに確認を手配し、#37で結果を追跡する。未完了なら公開を延期する。

DiscordのAPI制限は [Bot仕様](11-discord-bot.md) の通り。Rate limitを固定値にしない。Discord過去メッセージを人格作成のために収集しない。

MVPのAPI目安は認証済みユーザー60リクエスト/分、書込10リクエスト/分、人格提案3回/日。初期はAPI 1インスタンスのメモリ内制御にし、LLM費用はDB台帳で厳格に止める。APIを複数台に増やす前に共有ストア型のレート制限を導入する。制限値は負荷試験後に調整し、429に`Retry-After`を返す。

## アイコンの画像検証と用途分離（#15）

PNG/JPEG/WebPの実データを完全デコードして新しいPNGへ再エンコードし、EXIF/GPS・コメント等を
Storageへ渡さない。MIMEだけの判定は行わず、2 MiB/2048px/単一フレームをAPIで検証する。
本人の招待認可→アップロード/registry登録→本人registryにあるパスのみ選択、の順を守る。
UUID採番＋upsert=false＋Storage RLSで既存画像への差替えを防ぐ。公開bucketは作らず、
表示用画像のprivate bucketだけへ300秒の署名URLを出す。私的ファイルbucketのURLは発行しない。
StorageキーはAPI専用`SUPABASE_STORAGE_SECRET_KEY`、Auth管理の`SUPABASE_SECRET_KEY`とは
用途を分け、Web/Worker/Botへ配布しない。署名tokenは再送記録/監査/エラーに保存しない。
発行済みURLは解除/失効後も最大300秒利用できる。画像の清掃/削除は#30へ接続する。


### #18 LLM実行の保護

人格提案の3回/UTC日はメモリではなくDBで直列化し、失敗も数える。
公開項目の辞書だけを受理し、非公開欄・メール・トークン・既知サーバー秘密を送信前に拒否する。
schema制約/ローカルルール/独立したSonnetの安全性判定をすべて通った公開出力だけを返す。
人格を自動保存・自動承認せず、生成中の招待失効/削除も再確認する。
LLM通信中はDBトランザクションを保持せず、既知の費用は失効後でも必ず記録する。
結果不明/プロセス停止は永続状態と残予約を保持し、そのAIの追加LLM実行を止める。
llm_runsは本文/秘密を保存しない。利用者応答・例外・ログにも供給元本文を出さない。
全有害表現の検出を保証するものではなく、#37で日本語・安全性・誤検知を実受け入れする。
