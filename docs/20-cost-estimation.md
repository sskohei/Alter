# 運用費の概算（USD/月）

配置方針更新日: 2026-11-14（ADR-015、#75）。初期MVPはWeb/DBの無料枠と運営者の既存PCを使う。無料枠の条件は公開前に再確認し、LLM費・電気代・回線・任意の公開経路/ドメイン費用を分けて見積もる。

## 初期MVPの固定費

| 項目 | 採用 / 契約費の目安 | 条件・対象外 |
|---|---|---|
| Web | Vercel Hobby $0/月 | [公式条件](https://vercel.com/docs/plans/hobby)。個人・非商用と使用量制限を満たすこと |
| DB/Auth | Supabase Free $0/月 | [公式価格](https://supabase.com/pricing)。無料枠は500MB DB・有効プロジェクト最大2件、非稼働1週で休止。本番/Previewを分離し、既存プロジェクトも数える |
| API/Worker/Bot/Scheduler | 既存の手元PC、追加サーバー契約 $0/月 | PC購入代・電気代・既存回線費は別。停止/スリープ/回線断時は利用停止 |
| API公開HTTPS経路 | 未選定（#34） | 無料条件・固定URL・ブラウザ/SSR疎通を確認。追加費用が必要なら再見積もり |
| バックアップ | 既存の別保存先の範囲で運用 | Supabase Freeの自動バックアップは前提にしない。保存先を購入する場合は別費用 |
| インフラ固定契約費小計 | **$0/月を目標** | 無料枠と追加課金不要の公開経路/保存先が成立する場合。LLM・電気代・回線・ドメイン等を含まない |

無料枠の確認日: 2026-11-14。無料枠内であることや24時間稼働は保証しない。稼働時間と停止時の制約は[デプロイ](14-deployment-infrastructure.md)に従う。Vercelの用途条件を満たさない場合や、Supabase容量/転送量/プロジェクト数を超える場合はプラン/構成を再検討する。100人/1,000人向けも無料で足りるとは見込まず、PCのメモリ/CPU、ジョブ待ち、DB容量、回線を実測して見積もる。

PCの追加電気代の目安は `平均消費電力(W) ÷ 1000 × 稼働時間(h/月) × 電力単価(円/kWh)`。例えば仮定30W・24時間×30日・31円/kWhなら約670円/月。電力単価/消費電力は説明用の仮定であり実測値ではない。

旧Render分離構成のAPI/Worker/Bot/Cronの固定費は初期MVPでは発生しない。VPS/Render等への移行は、常時稼働や負荷・運用の必要性が出た段階で再見積もりする。

## Claude Sonnet 5.5: 10人MVPのLLM使用量モデル（#14）

2026-11-13、sskoheiの指示によりAnthropic直接APIの`claude-sonnet-5-5`を正式採用。
[公式通常単価](https://platform.claude.com/docs/en/models/sonnet-5-5/overview)は、
入力$2 / 出力$10（各100万tokens）。thinkingは出力に含める。割引や無料枠は見込まない。
採用設定の上限は入力3072 / 出力512 tokens（2026-11-14レビュー対応で入力上限を縮小）。上限まで使うことと予算内に収まることは別条件である。

仮定: 10人、1人1日1交流参加、2人/会話、30日で150会話。
8発言で各入力1500/出力200 tokens、要約予備は入力2000/出力300。
合計入力14000 / 出力1900 tokens、追加20%予備費。
`1会話 = (0.014 × 2 + 0.0019 × 10) × 1.2 = $0.0564`。
記憶候補は追加LLM不要。#95の会話要約は完了後に別予約する。moderation/人格提案の追加呼出は別途予約する。

| 項目 | Sonnetの概算 |
|---|---:|
| 1会話・20%予備費込み | $0.056400 |
| 150会話/月 | $8.460000 |
| 1人1日2交流参加、300会話/月 | $16.920000 |
| インフラ固定契約費$0＋150会話の生成費 | 約$8.46/月（電気代等は別） |

**実測・最大費用の保証ではない。** 入力/出力、thinking、moderation、人格提案、再試行、
税/為替により変動する。購入時$5は現在残高/有効期限を保証せず、この仮定の月間費用を下回る。
供給元のクレジット残高も運営が確認する。

## 会話/日次上限との関係

入力3072 / 出力512（thinking込み）を毎回使うと1呼出$0.011264。
会話最大8発言なので、AI 1体の4発言分の最大生成予約は**$0.045056**。
SQL正本の既定値`max_session_usd=$0.05`以内で、1体が日次2会話参加しても
$0.090112となり`daily_budget_usd=$0.20`以内。2体合計で1会話$0.090112、
10人が日次2回参加する10会話/日の生成分は最大$0.901120。
残予約や他のusage、運営全体の上限も独立して検査するため、常に開始できる保証ではない。

2026-11-14、[PR #57の指摘](https://github.com/sskohei/Alter/pull/57#issuecomment-6854464943)に対し
入力上限を下げる方針を採用。4096入力では4発言で$0.053248となり、既定枠に収まらないため
3072とした。DB既定値の引上げや発言ごとの予約方式への変更は行わない。
`alter_domain.llm_selection.session_generation_reservation()`が会話生成分の予約額を返す。
#14の評価CLIは生成分の上限を使う。本番の#19/#20は下記の安全判定込み予約を使う。
既存のfake Workerの仮の巨大token見積を実Sonnetへ流用しない。

記憶候補は検査済み発言の引用で作り、追加LLM呼出を0とする（#22）。
#95の会話要約は生成3072/512＋独立判定768/16で、最大$0.012960を残枠から予約する。
会話/日次/全体の上限は上げず、残予算が足りなければ要約を作らない。
4発言後の既定枠の余裕は$0.004944。5回目も最大量で呼ぶと$0.056320で枠を超えるので、
追加の有料moderation/要約等は別の小さな上限で残枠に含めるか、生成量を減らす。
#18で独立安全判定をinput512/output16に制限し、1回最大$0.001184を追加した。
1体4回の判定は$0.004736、生成と合計して**$0.049792**で既定枠内。
`session_reservation()`を会話予約の正本とする（`session_generation_reservation()`は生成分だけ）。
日次2会話/AIは$0.099584、2体/会話は$0.099584、日次10会話は最大$0.995840。
提案は生成＋判定で1回最大$0.012448、UTC日次3回で最大$0.037344/AI。
提案や他usageも同じ日次/全体台帳に含むので、全枠を同時に使える保証ではない。
上の平均生成費の仮定に判定分の最大予約を足すなら150会話/月で最大$1.4208追加となる。
判定入力が512枠に収まらなければ未呼出で停止し、生成の既知実費だけを記録する。

再試行は供給元で**未処理/未課金と確認できた失敗だけ最大3回**とし、課金結果不明なら
追加呼出せず予約を保持して照合する。したがって未課金の再試行は会話の有料呼出数を増やさない。
課金された拒否/不正出力を無条件で再生成しない。有料の再生成を追加する場合も
残予約/会話/日次/全体枠で検査し、今回の$0.045056に含まれると扱わない。

入力上限3072にはsystem・schema・公開人格・引用記憶・履歴を含む。
count_tokensの見積＋余裕1024が上限を超えたら実APIを呼ばず停止する。
#18では公開人格と安全命令を残し、古い履歴/引用contextを削って再計数する。
切り詰めても枠内に収まらない場合は停止する。token計数は推定で、実usageが上限を超えたら
呼出を停止して照合する。長い人格/全10場面の新上限での実評価はまだ行っていない。

Sonnetの限定実評価は31生成、usageからの計算$0.098204、最大見積予約$0.286002。
[評価記録](../evaluations/llm/sonnet-review-2026-11-13.md)を参照。請求明細は未照合。

不足時は安全に止め、`--scene`で対象を分けて明示的な予算で実行する。

大人数向け最適化は対象外。インフラ拡張欄は将来参考値に留める。
