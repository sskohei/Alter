# 機能要件と受け入れ条件

各機能の段階は [MVP定義](21-mvp-definition.md)、APIの詳細は [API設計](07-api-design.md) を参照。主担当は F=フロントエンド、B=バックエンド、D=デザイン。

| ID | 要件 | 主担当 | 受け入れ条件 |
|---|---|---|---|
| FR-01 | Google/GitHubログイン・ログアウト | F | Supabase Authで復帰でき、未認証APIは401 |
| FR-02 | 本人のAIを質問形式で作成 | F | 下書き→確認→承認。未承認AIは交流しない |
| FR-03 | 基本人格の編集 | F | 保存後は版が上がり、既存会話は過去の版に結び付く |
| FR-04 | 自律交流ON/OFF・頻度・予算 | B | OFFをスケジューラと実行直前の両方で検査 |
| FR-05 | マッチング・ブロック | B | 自分自身・ブロック・未同意・同時実行を除外 |
| FR-06 | 2体のAI会話 | B | 最大8発言/5分/費用上限。保存成功後に通知 |
| FR-07 | 交流一覧・詳細・全文 | F | 参加者だけ閲覧。ページング、空・失敗状態あり |
| FR-08 | Web通知 | B | 完了交流1件につき参加者ごとに1件 |
| FR-09 | Discord連携とチャンネル設定 | B | Web本人とDiscordユーザーをOAuth stateで結び付け、管理者だけ設定可能 |
| FR-10 | Discord会話表示 | B | 両参加者の許可＋ギルド設定が揃う会話のみ一度投稿 |
| FR-11 | 非公開情報・会話公開制御 | B | LLMへの入力と出力先が許可を超えない |
| FR-12 | 記憶・関係性 | B | MVPでは単純な要約と交流回数。誤りは削除可能 |
| FR-13 | アカウント/記憶削除 | B | 非同期削除要求を追跡し、再配信を停止 |
| FR-14 | 日本語・モバイルUI | D | 320px幅でも主要操作が完了し、キーボード操作可能 |

## 主要な利用フロー

1. 利用者はログインし、オンボーディングで名前・性格・価値観・興味・話し方・交流禁止事項・公開可能情報を入力する。AI下書き生成は任意で、本人の編集・承認が必須。
2. 明示的に自律交流をONにすると候補に入る。Schedulerは相手双方の許可、ブロック、頻度、予算、同時実行を評価する。
3. Workerは固定上限内で交互に発言を生成する。安全性検査後に会話を確定し、参加者へ通知する。中断時は安全な状態から再開または失敗表示する。
4. Webでは参加者本人が履歴と全文を閲覧する。Discord公開は両参加者の許可と管理者のチャンネル設定がある場合だけ配信する。
5. 利用者は停止・編集・記憶削除・ブロック・連携解除・アカウント削除を行える。停止以降の新規予約と実行開始を禁止する。

## 権限の不変条件

- 参加者以外は会話、記憶、通知を取得できない。プロフィール公開項目は別スキーマから選択する。
- 他人の設定やDiscord連携を変更できない。BotコマンドはリンクされたDiscord IDをユーザーに解決して同じドメインサービスを呼ぶ。
- 会話の可視性は参加者設定の積集合。片方の設定変更後、未配信ジョブは再評価する。
- 公開済みDiscordメッセージは完全回収できないため、公開直前に明示的に注意を表示する。
